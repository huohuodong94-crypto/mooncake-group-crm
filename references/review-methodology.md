# 团购复盘方法论（判断层）

引擎（`scripts/crm.py summary`）只产出**确定性计数**；“这说明什么、下一步怎么办”由 Agent 依本文件判断。做周/月复盘前**必须先读本文件**，再读引擎输出的 JSON，最后才下结论。单条录入/查询不需要读本文件。

## 1. 漏斗阶段口径

以双表“当前阶段”7 态为准，复盘按以下漏斗归并：

```
初次接触 → 需求确认 → 方案报价 → 谈判中 → 已签约 → 已回款
     └──────── 任一未成交阶段可进入已流失 ────────┘
```

- **在谈盘子（pipeline）**＝当前阶段 ∈ {初次接触, 需求确认, 方案报价, 谈判中} 的商机，金额用 `预计金额` 求和。
- **已签约**＝阶段历史曾进入“已签约”的商机，采用累计里程碑口径；商机进入“已回款”后仍计入已签约数。
- **已回款**＝当前阶段=已回款；金额优先使用回款金额。签约数、回款数和回款金额分开报告，不使用单一“已成交”口径。
- **流失**＝阶段=已流失，按 `流失原因` 归类取 Top。

转化率：`签约转化率 = 已签约数 / (已签约数 + 已流失数)`；如需计算报价→签约率，分母必须来自阶段历史中曾进入“方案报价”的商机。分母样本 < 5 条时只报绝对数，不报百分比（避免小样本误导）。

## 2. 跟进健康度

- **逾期**＝非终态且 `下次跟进日期 < 今天`。逾期是**最强预警**，复盘必须点名到商机编号 + 跟进人。
- **今日到期**＝`下次跟进日期 == 今天`；**将到期**＝未来 7 天内。
- **意向×逾期交叉**：A 类逾期 > B 类逾期 > C 类逾期，优先处理高意向逾期。
- **无下次跟进日期**的非终态商机列入**跟进断档**。A/B/C 级或“方案报价”阶段必须补齐；D 级无默认提醒天数，需单独标注并请店长决定是否排期，不能擅自生成日期。
- 健康度评级（判断层）：逾期率 = 逾期数 / 非终态商机数。`<10%` 健康；`10–30%` 需关注；`>30%` 失控，需在复盘开头标红提示。

## 3. 成交归因的证据等级

对“为什么成/为什么丢”的归因，按证据强弱标注，不夸大：

| 等级 | 依据 | 可用措辞 |
|---|---|---|
| 强 | 有明确跟进记录/客户反馈/流失原因文本直接支撑 | “因 X 成交/流失” |
| 中 | 仅有阶段+金额+时间，无文本证据 | “疑似与 X 相关，建议回访确认” |
| 弱 | 仅凭统计相关（如某来源成交多） | “数据显示 X，暂无因果证据” |

禁止把弱证据写成强结论。流失原因空缺时归为“未记录”，并提示补录，不要替店长编原因。

## 4. 周/月复盘结构（输出顺序）

1. **一句话结论**：本期在谈盘子 / 回款金额 / 逾期数，三选最要紧的先说。
2. **漏斗快照**：七态阶段条数 + 在谈金额 + 已签约累计数 + 已回款数/金额。
3. **风险清单**：逾期 + 今日到期 + 跟进断档，点名到 `商机编号 / 客户 / 跟进人 / 意向等级`。
4. **新增与转化**：本期新增商机数、A/B/C/D 分布、转化率（样本不足则只报绝对数）。
5. **流失归因**：Top 流失原因 + 证据等级。
6. **下周重点**：从风险清单与高意向将到期里取 3–5 条，给具体动作 + 建议话术。
7. **数据缺口**：缺意向等级 / 缺下次跟进日期 / 缺流失原因 / 重复嫌疑客户，逐项列出让店长补。

## 5. 复盘质量门槛（不过不交付）

- 每个数字都能对应到引擎 JSON 的字段，无手算、无估算。
- 逾期清单非空时**必须**逐条点名，不得只报总数。
- 转化率/百分比要么样本≥5，要么明确标注“样本不足，仅供参考”。
- 归因措辞与第 3 节证据等级一致。
- 结尾必须给“下周重点 + 数据缺口”，否则复盘不闭环。

## 6. 数据缺口处理（Inversion）

复盘发现以下情况，**不要猜**，列入“数据缺口”交店长确认：

- 商机无意向等级 → 影响提醒节奏与优先级，要求补 A/B/C/D。
- A/B/C 级或“方案报价”阶段无下次跟进日期 → 跟进断档，要求补；D 级无日期单列为“未排期”，让店长决定是否安排。
- 已流失无流失原因 → 归因缺失，要求补。
- 客户名称相近但联系电话不同 → 疑似重复建档，要求人工合并/区分（引擎不自动合并）。
- 已回款但回款金额为 0 或空 → 回款口径存疑，要求确认。
