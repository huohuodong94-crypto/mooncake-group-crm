# 门店团购客户与商机管理助手——变更需求说明

**接收人：** 产品 / FDE  
**版本：** V1.2  
**日期：** 2026-08-10  
**优先级：** 一期范围内变更

## 1. 变更背景

原一期目标不变：跑通“语音新增/更新 → 信息确认 → 写入统一台账 → 生成回访任务 → 到期提醒 → 周度数据汇总”的最小业务闭环。

本次变更重点为：

1. 冻结门店客户商机表字段及排列顺序，新增公司地址字段；
2. 补充所属门店、线索来源、需求类别、意向等级、当前阶段等标准枚举；
3. 新增回款日期、回款金额、交货日期；
4. 按门店生成团单汇总报表；
5. 明确字段联动、校验、统计口径和待确认事项。

## 2. 一期业务范围

### 2.1 保持不变的核心闭环

店长通过手机端小龙虾口述或上传录音，AI识别客户和商机信息，经店长确认后新增或更新台账，并自动生成后续跟进任务。店长可继续通过语音更新报价、谈判、签约、回款、交货或流失状态，系统同步更新商机、跟进记录和汇总报表。

### 2.2 本次不新增的范围

仍不纳入一期：自动读取微信聊天、自动联系客户、复杂销售预测、自动审批报价。

## 3. 客户商机表变更

### 3.1 已确认表头及顺序

| 序号 | 字段 | 必填 | 类型/格式 | 录入与维护规则 |
|---:|---|:---:|---|---|
| 1 | 商机编号 | 系统 | 文本 | 系统自动生成，示例：`MO-2026-0001`；唯一且不可手工修改 |
| 2 | 客户编号 | 系统 | 文本 | 系统自动生成，示例：`KH-2026-0001`；同一客户的多笔团单共用客户编号 |
| 3 | 客户名称（企业名称） | 是 | 文本 | 新增前查重；允许同一客户创建多笔不同商机 |
| 4 | 公司地址 | 否 | 文本 | 新增字段，记录联系人所在地址，明确不是订单配送地址；归属客户信息 |
| 5 | 联系人 | 是 | 文本 | 客户侧主要联系人 |
| 6 | 联系电话/微信 | 是 | 文本 | 至少填写一种联系方式；保留电话、微信号及前导零 |
| 7 | 所属门店 | 是 | 单选 | 使用第4.1节枚举 |
| 8 | 线索来源 | 否 | 单选 | 固定使用第4.2节枚举；建议改为必填，便于来源分析 |
| 9 | 客户需求 | 是 | 长文本 | 记录用途、预算、规格、交期、定制要求等原始需求摘要 |
| 10 | 需求类别 | 否 | 单选 | 固定使用第4.3节附件1枚举；建议必填或允许“待定” |
| 11 | 意向数量（盒） | 否 | 非负整数 | 单位固定为“盒” |
| 12 | 意向等级 | 是 | 单选 | A-必成 / B-高潜 / C-跟进 / D-观望 |
| 13 | 预计金额 | 否 | 金额 | 人民币，保留两位小数，非负数 |
| 14 | 当前阶段 | 是 | 单选 | 使用第4.5节枚举 |
| 15 | 最近跟进情况 | 否 | 长文本 | 自动展示最近一条跟进记录摘要，不应覆盖历史跟进记录 |
| 16 | 下次跟进日期 | 条件必填 | 日期 | 按意向等级、商机阶段及店长明确口述的日期确定，详见第5.2节 |
| 17 | 跟进人 | 是 | 人员 | 默认当前店长，可修改；应关联账号，不能只存自由文本 |
| 18 | 回款日期 | 条件必填 | 日期 | 当前阶段更新为“已回款”时必填 |
| 19 | 回款金额 | 条件必填 | 金额 | 当前阶段更新为“已回款”时必填；人民币，保留两位小数 |
| 20 | 交货日期 | 否 | 日期 | 计划或实际口径需确认，见第8节 |
| 21 | 流失原因 | 条件必填 | 文本/单选+补充 | 当前阶段更新为“已流失”时必填 |
| 22 | 最后更新时间 | 系统 | 日期时间 | 每次新增或更新商机、跟进、回款信息时由系统自动刷新 |

### 3.2 公司地址字段说明

“公司地址”为本次确认新增字段，业务定义为联系人所在地址，不是配送地址。配送地址不得复用该字段；未来如增加订单履约，应另建配送地址字段或配送信息对象。

## 4. 标准枚举

### 4.1 所属门店

固定为5个门店：

- 月湖店
- 体验店
- 国金店
- 五一店
- 花样汇店

注意：报表附件中使用了“体验中心店”，需要与“体验店”统一为同一个标准名称，避免被统计成两个门店。

### 4.2 线索来源

线索来源枚举已确认为：

- 新获客
- 老客转介绍
- 老客续费

不新增“主动开发”等其他枚举值。存量或导入数据中的“主动开发”统一映射为“新获客”。

### 4.3 需求类别

需求类别已确认按附件1，固定为：

- 散装
- 68礼盒
- 98礼盒
- 138礼盒
- 定制礼盒
- 待定

不采用文字需求中出现的“59.8元简装/168月如意/268XXX/定制化/其他”版本。建议底层保存稳定的产品/规格编码，页面展示附件1中的名称。

### 4.4 意向等级

- A-必成
- B-高潜
- C-跟进
- D-观望

建议仅保存枚举代码A/B/C/D，页面展示“代码-中文名称”，便于后续名称调整而不影响历史统计。

### 4.5 当前阶段

按附件3更新为：

1. 初次接触
2. 需求确认
3. 方案报价
4. 谈判中
5. 已签约
6. 已回款
7. 已流失

阶段正常流转为：初次接触 → 需求确认 → 方案报价 → 谈判中 → 已签约 → 已回款。已流失为任一未成交阶段可进入的终止状态。

不保留“暂缓跟进”；原“谈判跟进”统一改为“谈判中”。

## 5. 字段联动与业务规则

### 5.1 客户与商机

- 新增前按“客户名称 + 联系方式”进行候选查重，并让店长确认是复用原客户还是新建客户。
- 同一客户再次发起团单时，复用客户编号，新建商机编号。
- “最近跟进情况”来自最新跟进记录；每次语音更新均新增一条跟进记录，保留时间、内容、客户反馈、下一步动作和跟进人，不只覆盖商机表上的摘要。
- 金额、数量、日期、客户名称、联系方式等关键字段必须在写入前由店长确认。

### 5.2 意向等级、阶段、日期和提醒联动

#### 默认跟进时限

| 条件 | 默认规则 |
|---|---|
| A-必成 | 3天内跟进 |
| B-高潜 | 5天内跟进 |
| C-跟进 | 7天内跟进 |
| D-观望 | 不做默认跟进要求 |
| 当前阶段=方案报价 | 报价后2天内回访 |
| 到期未完成 | 再次提醒，直至任务完成、重新安排日期或商机进入终止普通回访的阶段 |
| 已成交、已流失 | 停止普通回访提醒 |

以上天数先按当前规则实现为可配置参数，最终值由客户业务负责人确认；不应将天数写死在Skill提示词或代码中。

#### 规则优先级与执行方式

1. 店长明确口述并确认了下次跟进日期时，优先使用店长指定日期。
2. 未指定日期且当前阶段为“方案报价”时，使用报价后2天规则；该规则优先于A/B/C/D等级规则，包括D级商机。
3. 其他未指定日期的商机按A/B/C等级生成建议跟进日期；D级不自动生成普通回访任务。
4. 到期未完成时再次提醒；再次提醒的时间间隔和最大次数作为可配置项，由客户业务负责人确认。
5. 当前阶段为已签约或已回款时，视为“已成交”，停止普通销售回访。已签约但未回款的，可另建回款任务；已回款但未交货的，可另建交货任务，两者不属于普通回访提醒。
6. 当前阶段为已流失时，流失原因必填，并关闭未完成的普通回访任务。
7. 已签约、已回款、已流失及无跟进要求的D级商机，不应无条件强制填写“下次跟进日期”。表头星号按规则动态校验。

### 5.3 自动维护

- 商机编号、客户编号、最后更新时间由系统自动生成或更新。
- 跟进频次由跟进记录数量自动统计，不新增人工填写字段。
- 门店、跟进人、关键金额与日期的修改应留操作日志。
- 语音未识别出下次跟进日期时，继续按意向等级/阶段规则给出建议日期，店长确认后创建任务。

## 6. 语音识别与操作意图变更

语音助手需覆盖以下意图，并支持本次新增字段：

| 意图 | 示例 | 系统动作 |
|---|---|---|
| 新增商机 | “新增喜悦大酒店，总厨，计划采购200盒……” | 提取字段、查重、确认后新增客户/商机和跟进记录 |
| 更新跟进 | “今天给喜悦大酒店发了报价，下周一再联系” | 新增跟进记录，更新最近跟进、阶段和下次跟进日期 |
| 更新签约 | “喜悦大酒店已经签约” | 阶段改为已签约，关闭普通回访，创建回款任务 |
| 更新回款 | “喜悦大酒店8月10日回款14000元” | 写入回款日期、回款金额，阶段改为已回款 |
| 更新交货 | “这单8月20日交货” | 写入交货日期并更新相应提醒 |
| 更新流失 | “客户不做了，原因是预算取消” | 阶段改为已流失，写入流失原因并关闭回访提醒 |
| 查询 | “查询本周还没跟进的A级客户” | 按权限返回满足条件的商机清单 |

## 7. 团单汇总报表

### 7.1 展示结构

- 报表按门店横向展示，列至少包括：月湖店、体验店、国金店、五一店、花样汇店、合计、说明。
- 支持统计周期/截止日期筛选；所有数量、金额和比例必须基于同一筛选范围。
- 门店列建议根据门店主数据动态生成，避免新增门店时修改报表代码。

### 7.2 指标及建议统计公式

| 指标 | 统计口径/公式 |
|---|---|
| 团单总数 | 去重后的商机编号数量 |
| A-必成 | 意向等级=A的商机数 |
| B-高潜 | 意向等级=B的商机数 |
| C-跟进 | 意向等级=C的商机数 |
| D-观望 | 意向等级=D的商机数 |
| A级占比 | A-必成商机数 ÷ 团单总数 × 100%；总数为0时显示0% |
| 预计总金额 | 预计金额合计；是否排除“已流失”见第8节 |
| 各需求类别数量 | 对应需求类别的商机数；类别名称以最终冻结枚举为准 |
| 已签约数 | 已完成签约里程碑的商机数，建议包含当前阶段已进入“已回款”的商机 |
| 已回款数 | 已完成回款里程碑的商机数 |
| 已流失数 | 当前阶段=已流失的商机数 |
| 谈判中数 | 当前阶段=谈判中的商机数 |
| 签约转化率 | 已签约数 ÷ 团单总数 × 100%；总数为0时显示0% |

说明：附件4中的示例数据为3/59=5.1%，说明签约转化率的分子直接使用“已签约数”。但需进一步确认“已签约数”是否为累计到达签约里程碑的数量。本文建议采用累计里程碑口径，即商机从“已签约”进入“已回款”后仍计入已签约数，已回款数是其中的子集，避免低估签约转化。系统需要保留阶段变更历史，不能只依赖当前阶段反推。

### 7.3 数据一致性要求

- 各门店合计必须等于“合计”列。
- A/B/C/D数量合计原则上应等于团单总数；若意向等级必填，则不允许出现未分级差额。
- 报表需求类别需与商机表需求类别枚举完全一致。
- 报表应按商机“所属门店”归属，不按跟进人所在门店临时归属。
- “谈判中、已流失”等当前阶段统计为互斥快照；“已签约数、已回款数”若采用累计里程碑口径，则两者允许包含关系，不要求互斥。

## 8. 开发前必须确认的口径

以下问题若未确认，会造成字段、统计或提醒逻辑返工：

1. “体验店”与“体验中心店”的最终标准名称。
2. A/B/C等级及报价后的默认跟进天数，最终由客户业务负责人确认；到期未完成后的再次提醒间隔和最大次数也需确认。
3. 回款是否可能分多次：若支持分期/多笔回款，应建立回款明细（回款日期、金额可多条），商机表只展示累计回款金额和最近回款日期；不能只用一组字段覆盖。
4. 交货日期记录“计划交货日”还是“实际交货日”；若两者都需要，应拆成两个字段。是否存在分批交货。
5. 预计总金额是否包含已流失商机。建议默认不包含已流失，同时允许报表查看含流失的历史总盘。
6. 报表是“截至某日的当前快照”还是“统计期内新增商机”。建议提供统计模式或明确采用截至日快照。
7. “已签约数”是仅统计当前阶段=已签约，还是统计所有已到达签约里程碑（包含已回款）；本文建议采用后者，并按“已签约数÷团单总数”计算签约转化率。
8. 成交口径最终以已签约、已回款还是完成交货为准；建议分别展示签约率、回款率，不混用。
9. 最终表头没有签约日期。若报表需要按周期统计新增签约数，需补充签约日期字段，或确保阶段历史中保存进入“已签约”的准确时间。

## 10. 一期验收标准

1. 店长可通过语音新增商机，系统能提取并确认全部必填字段后写入台账。
2. 同一客户的第二笔团单能复用客户编号并生成新的商机编号。
3. 店长可通过语音更新阶段、回款日期、回款金额、交货日期和流失原因。
4. 每次更新均新增历史跟进记录，并正确刷新最近跟进情况和最后更新时间。
5. 未明确下次跟进日期时，A/B/C级分别能按3/5/7天生成建议任务，D级不自动创建普通回访；方案报价按2天规则优先处理。
6. 到期未完成能再次提醒；已签约、已回款和已流失能停止普通回访，回款及交货任务可独立保留。
7. 必填及条件必填校验有效，金额、日期、数量识别结果在写入前可确认和修改。
8. 汇总报表能完整展示5个门店及合计，各指标与台账抽样核算一致。
9. 店长只能查询和维护其权限范围内的数据；总部角色可查看跨门店汇总。

## 11. FDE实施建议

数据层仍建议拆分为客户、商机、跟进记录、回款记录/成交信息四类对象；前端可继续用一张“客户商机表”作为统一视图。这样既满足店长使用简单，也能支持同一客户多笔商机、多次跟进和潜在的多笔回款，避免后续因扁平表覆盖历史数据而返工。
